# STM32：UART 与调试记录

原创学习示例；未做硬件上板测试。

## 通信前先填写

芯片与板卡版本、UART 或 USART 实例、TX/RX 引脚及复用功能、对端设备与电平、连接方式：待核对。波特率、数据位、校验位、停止位和流控：待填写。双方设置必须相符，具体参数由实际工程决定，本例不指定一套通用接线。

## 从单向输出开始

先规划一条短的固定消息，确认需要发送的字节和结尾，再配置实际使用的串口。检查外设时钟、引脚复用、收发方向以及初始化调用顺序；同时记录终端软件选择的设备和通信参数，避免仅修改单片机一侧。

第一轮只做发送，预期是对端收到完整、可重复辨认的消息。若没有输出，分开检查程序是否运行到发送位置、是否使用了预期外设、对端是否打开正确设备。收到乱码时核对通信格式、时钟依据与消息编码，不先把所有问题归咎于波特率。

发送路径确认后，再尝试接收固定长度数据，并明确缓冲区容量、结束条件和超时处理。先验证一次完整交互，再学习中断或 DMA 接收；没有说明消息边界时，不把“收到若干字节”直接当作完整命令。

## 让日志能够帮助排查

每条调试记录包含工程版本、改动项、测试步骤、预期消息、实际收到的内容和下一步。区分串口输出与调试器控制台输出；某处文字能够显示，不自动证明目标 UART 已正常工作。关键故障保留原始字节或日志，不只写“串口不通”。

- [ ] 双方参数与实际接线已按文档核对，未知项未用示例值填补。
- [ ] 记录发送、接收和超时分别是否验证，未执行写“未测试”。
- [ ] 重试前说明只改变了哪一项；没有上板或波形记录时不声称通信成功。
