# STM32：板卡信息与最小工程学习路线

原创学习示例；未做硬件上板测试。

## 先填写工程身份

- 芯片完整型号与封装：待填写；开发板名称和硬件版本：待填写。
- 原理图、数据手册与参考手册：待补官方链接，并记录版本。
- 供电方式、调试接口、下载器型号：待核对；不要从相似板卡猜接线。
- 时钟来源、启动配置、工具链和固件包版本：待填写；保留工程配置文件。

## 从空工程走到可观察的动作

先区分三个目标：编译通过、程序能够下载、预期行为可以观察。前一项通过不能代替后一项。依据实际芯片选择开发环境与固件包，先阅读对应系列的入门说明，不直接照搬其他系列的引脚和时钟配置。

第一轮只建立最小工程，查看启动文件、链接脚本和主函数之间的关系。记录芯片选择、工程名称、构建方式和输出文件；若编译失败，先保留第一条错误及其上下文，再检查依赖和配置，不同时修改多项设置。

具备真实板卡后，再核对供电与调试连接，尝试下载并在主函数附近停住。将“连接成功”“下载完成”“断点命中”分别记录。随后选择一个已从原理图确认的可观察对象，按顺序学习输出、输入和串口；每次只增加一项能力，保留前一个可工作的版本。

## 验证清单与记录

- [ ] 型号、板卡版本与官方文档能够对应，未知项仍标待核对。
- [ ] 保存构建日志，确认输出文件来自本次构建。

- [ ] 记录本轮改动、预期现象、实际现象与下一步；没有测量数据时不填写示例数值。
