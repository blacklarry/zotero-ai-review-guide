# Obsidian 科研知识库 · 从空目录开始

把课程、文献、研究问题、数据、实验和论文组织成可回溯的工作流。本方案从真实使用中的目录与整理规则提炼，公开包中的内容已改写为通用模板；三篇演示记录均为虚构占位，不包含真实研究结论。

- [下载知识库起步包](https://blacklarry.github.io/zotero-ai-review-guide/downloads/knowledge-base/knowledge-base-starter.zip)
- [站点知识库教程](https://blacklarry.github.io/zotero-ai-review-guide/#knowledge)

这是一份可直接打开的 Markdown 文件夹，不包含 Obsidian 安装程序、社区插件、同步配置、账号、私人文献或原始数据。现有 Zotero 接入教程可继续用于文献检索；本包负责整理笔记和研究证据。

## 1. 新建一个独立知识库

1. 先自行安装并打开 Obsidian；本包不安装任何软件。
2. 将 ZIP 解压到一个新的空目录，得到 `research-vault/`。不要直接覆盖已有知识库。
3. 在 Obsidian 中选择“打开本地仓库”（界面文字可能随语言和版本变化），选中 `research-vault` 文件夹，而不是 ZIP 或其外层目录。
4. 打开 `00_开始这里.md`，顺着入口阅读知识库约定、示例课题、论文工作台和主题 MOC。
5. 有旧库时，先做备份，再挑选需要的模板与目录合并；同名文件先比较内容，不要覆盖原笔记。

Obsidian 将知识库保存为本地文件夹。[官方：创建或打开知识库](https://help.obsidian.md/Getting+started/Create+a+vault)

## 2. 先理解目录，再开始记笔记

| 目录 | 放什么 | 典型去向 |
| --- | --- | --- |
| `00_Inbox` | 临时链接、灵感、待判断材料 | 整理后移入对应目录 |
| `01_Daily` | 当日计划、待办、复盘 | 不代替正式实验记录 |
| `02_Courses` | 课程笔记、作业过程 | 按学期与课程组织 |
| `03_Literature` | 文献元数据、摘录、阅读理解 | 对应 Zotero 条目 |
| `04_Research` | 研究问题、数据集、实验、算法、结果、周报 | 按课题组织过程证据 |
| `05_Projects` | 工程需求、配置、调试、测试与交付 | 按项目组织 |
| `06_Knowledge` | 可跨课程、课题复用的方法与概念 | 按领域路径与 MOC 组织 |
| `07_Thesis` | 论证矩阵、章节草稿、图表与引用检查 | 链接证据，不重复整份日志 |
| `08_Outputs` | 已提交、已投稿或已交付的正式版本 | 记录版本与日期 |
| `09_Templates` | 九种可插入的笔记模板 | 先选类型，再填事实 |
| `10_Assets` | 跨主题复用的 PDF、图片等附件 | 不强制搬迁 Zotero 附件 |
| `98_Docs` | 工具、流程和环境说明 | 保存可复用操作约定 |
| `99_Archive` | 已结束且短期不再维护的内容 | 归档前检查入链与附件 |

文件夹负责用途与生命周期。研究课题是过程证据的家，论文目录是论证与写作的家，知识目录是跨任务可复用结论的家。

## 3. 打开核心模板功能

1. 在 Obsidian 的设置中启用核心插件“模板 / Templates”。
2. 将模板文件夹设为 `09_Templates`。
3. 先在目标目录新建并命名笔记，再通过命令面板的“插入模板”选择模板。
4. 插入后填写属性与正文，删除不适用项；不要直接在模板原文件中写实际记录。

包内九个模板：阅读笔记、知识笔记、研究问题、数据集档案、实验记录、项目主页、论文章节、MOC、课程笔记。

模板只使用核心插件能替换的 `{{title}}` 与 `{{date:YYYY-MM-DD}}`。标题取当前文件名，日期取插入时的日期；它们不会自动推断作者、来源、数据版本或文献发表日期。YAML 中的变量加了引号，其他空白字段需要手填。

- `created` 是笔记创建日期；`updated` 由使用者在修改后维护，并非自动更新。
- `publication_date` 是来源的发表日期，未知写“待核验”，不要用今天的日期代填。
- 属性值保持字符串、数字或日期等标量；模板中的状态与正文 `#status/...` 要同步。
- 数据集版本、代码 Commit、研究编号等均需从实际材料核验，不能由 AI 补造。

不依赖 Templater、Dataview 或其他社区插件。[官方：Templates](https://help.obsidian.md/Plugins/Templates)

## 4. 用标签表达属性，用链接表达主题

正文统一放一行属性标签，例如：

```text
标签： #type/阅读 #status/进行中 #source/论文
```

- `#type/...` 表示笔记类型，例如阅读、研究问题、数据集、实验、MOC。
- `#status/...` 表示待处理、进行中、阻塞、已完成、已归档等状态。
- `#source/...` 可选，表示论文、网页、课程等来源形式。
- 领域放进目录与主题 MOC，不再用另一套领域标签重复分类。

Obsidian 也支持属性中的标签；本方案为保持可见样式一致，统一采用正文 inline 标签。这是组织约定，不是软件限制。

内部链接使用准确的笔记名称或库内路径。重命名或移动文件后检查入链；重名时优先用完整库内路径。先写清“为什么有关”，再建立链接，不硬凑链接数量。[官方：内部链接](https://help.obsidian.md/Linking+notes+and+files/Internal+links)

MOC（Map of Content，主题地图）命名为 `0_MOC - 主题名.md`，放在主题目录中。主题积累约五篇笔记、频繁用于研究或写作时，就可以建立 MOC；五篇是本方案可调整的经验值，并非 Obsidian 的强制门槛。MOC 应包含主题范围、阅读路径、关键问题与输出方向，不只堆链接。

## 5. 建立一个课题，再串起证据

包内 `04_Research/示例课题/` 提供一个空白课题骨架：

```text
示例课题/
  00_课题主页.md
  01_研究问题/
  02_数据集/
  03_实验记录/
  04_模型与算法/
  05_结果与图表/
  06_周报与汇报/
  07_设备与采集/    可选；纯软件课题可略
```

从模板填写研究问题、数据集档案、实验记录，让同一课题的 `research_id` 一致。每次实验至少记录代码 Commit、数据版本与划分、环境、参数、随机种子、结果位置、失败现象和适用边界。没有做过的实验标记“未执行”，未知信息保留“待核验”。

推荐的回溯路径：

```text
论文论断 / 图表
  → 结果说明与处理脚本
  → 实验记录（代码、参数、环境）
  → 数据集版本与划分
  → 数据来源、采集记录或文献来源
```

文献证据则从论断回到阅读笔记，再回到 Zotero 条目、DOI/来源链接和原文页码或章节。AI 的总结只是待核验材料，必须回到原文或原始记录检查。Zotero 管理原文与引用，知识库保存理解、关系和研究过程，减少无必要的重复复制。

包内三篇演示笔记只用于展示有效链接与字段，状态均为虚构占位、未开展研究；不能作为论证、实验结果或数据来源引用。

## 6. 从课题进入论文工作台

打开 `07_Thesis/00_论文工作台.md`，先填写“主张—证据—来源—边界—状态”矩阵，再开始章节写作。用论文章节模板在这里创建章节，链接到课题中的真实证据，检查引用页码、图表编号和论断边界。完成并提交的版本放入 `08_Outputs`，保留提交日期、版本和文件位置。

## 7. 附件、隐私与备份

- 单篇笔记使用的图片优先放在同级 `images/`；跨主题复用的附件放进 `10_Assets`。可在设置中选择合适的附件默认位置。[官方：附件](https://help.obsidian.md/Editing+and+formatting/Attachments)
- PDF 已由 Zotero 管理时，记录其条目链接与定位信息即可，不必复制一份。移动附件后检查链接。
- 大型原始数据保存在适合的数据存储中，笔记只记录受控位置、版本、校验值和访问方法；公开分享时移除私人路径、受限数据和凭据。
- 合并、批量重命名或归档前，先把整个库复制到独立备份位置，并带上必要附件。定期保留可恢复版本，实际测试一次恢复；同步不能代替历史备份。
- 如使用 Git 或云同步，自行选择并配置权限与忽略规则；本包不自带同步、云端或插件配置。不要把私人日记、研究原始材料、密钥或未公开结果直接推送到公开仓库。

## 完成后的验收清单

- [ ] `00_开始这里.md` 中的说明、课题、论文、MOC 链接都能打开。
- [ ] 核心模板目录设为 `09_Templates`，九种模板可以插入。
- [ ] 新建笔记后 `{{title}}` 和 `{{date:YYYY-MM-DD}}` 被替换，其他事实字段已手填或明确待核验。
- [ ] 阅读笔记保留来源与定位，未知发表日期仍为“待核验”。
- [ ] 研究问题、数据版本、实验和论文论断能沿链接回溯；虚构演示未被当作研究证据。
- [ ] 附件链接正常，做过一次备份与恢复检查。
- [ ] 需要公开的内容已单独检查隐私、许可与未公开材料，不直接公开整个私人库。
